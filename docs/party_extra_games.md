# 数字炸弹与盲猜计时

入口在 FUN 菜单末尾：`Number bomb` 和 `Time guess 1-10s`。均为 2–4 人；一台 CREATE ROOM，其余 JOIN ROOM。各按下并松开准备，全员准备后连续 5 秒没有新人加入就锁定名单开赛。取消准备/新人加入会重置等待；开赛后不能中途插入。

## Number bomb

- 房主随机藏一个 1–100 的整数，只有房主内存保存炸弹；比赛快照不公开答案。
- 按大厅加入顺序轮流猜，房主先猜。屏幕显示当前仍可能包含炸弹的范围和轮到的玩家。
- 轮到自己时转旋钮选整数，短按提交；未命中则范围缩小并轮到下一位。
- 命中者本局出局，公布炸弹数字与出局者。当前回合 20 秒不提交也判出局；当前玩家掉线亦判出局。
- 客户端提交会重传，房主用轮次/名单版本/玩家身份校验，只执行一次，拒绝抢回合或范围外数值。
- 全员按键确认下一局后，回到大厅重新准备。

这是每局一位输家的玩法，不是持续淘汰到最后一人的长局。其他人在结束页统一进入下一局。

## Time guess 1-10s

- 每轮随机抽取 **1–10 秒的整数目标（含 1、10）**，所有玩家目标相同。
- 名单锁定时公布目标，随后各机随机等待 2–5 秒，屏幕出现 `GO! COUNT SILENTLY` 开始计时。
- 凭感觉默数，到目标时按旋钮停止。游戏中不显示已过秒数。
- 以按下沿时间戳计算本机用时，按与目标的绝对误差排名；提前和延后同样扣误差，相同误差并列。
- 成绩页示例 `#1 7.080s E80ms` 表示第 1 名、用时 7.080 秒、误差 80 毫秒。
- GO 前按下为抢按；GO 后 20 秒未按为 DNF。无线传输耗时不计入成绩。
- 这不是所有设备严格同时开始：各机本地显示 GO 后计时，避免把 BLE 延迟当成绩。

## 兼容与测试

两种游戏有各自的消息类型和房间过滤，不会与反应赛互相入房。无分区/NVS/storage ABI 变更。所有参赛机需要安装包含对应玩法的新固件。广播是娱乐协议，不具有密码学防作弊；屏幕刷新/消抖仍有计时误差。

`tools/test_party.c` 使用四个独立生产状态实例模拟比赛，覆盖 1–10 目标生成、目标同步、误差与并列、抢按/20 秒超时、猜数顺序和范围缩小、答案隐藏、丢包重传、旧版本/重复猜测、下一局和回合掉线。运行方法见 `nearby_games.md`。这是宿主模拟，不是四台射频实测。

双机截图/日志辅助验证：

```powershell
python tools/smoke_party.py --game time --out build/time-smoke
python tools/smoke_party.py --game bomb --out build/bomb-smoke
```

每次从重启后的默认主菜单状态启动脚本。脚本不修改持久设置；会提交游戏动作，成绩仅用于流程验收，不是人的实际反应或计时水平。脚本自动确认页面/无崩溃，具体成绩与范围同步仍需查看屏幕证据。

### 2026-10-20 双机验收

COM9 和 COM10 已烧录同一版，写入哈希校验通过。保存屏幕人工核对：计时回合两台均显示目标 4 秒，榜单对同一玩家显示相同用时、误差及名次，并可进入下一轮；数字炸弹实际依次提交 50、25、12、18、15、16，双方同步看到范围逐步缩小至 17..17，随后命中 17、公布一致的出局者，双方确认下一局后均回到 2/4 人、0 人准备的大厅。脚本日志无崩溃/栈检查失败。四人场景仍为宿主模拟，不是四台射频实测。
