# 半部电台：实验性多跳自组网

这是一版可手动开启的 BLE 受限泛洪中继，不是标准 Bluetooth Mesh，不用路由器或互联网。入口：**工具 → 自组网状态 / Local mesh network**（工具列表第九项），下一项为网络诊断。网络页已补中文，跟随设置中的语言开关。

10 月 27 日新增[离线留言、全网公告和多跳群聊](network_messages.md)。公告可跨频道；离线留言仅由发送设备持久排队，不等于中继长期缓存。下方 10 月 26 日记录是上一轮版本的实机证据，不能冒充新功能已通过射频验收。

## 操作

- 默认 `MESH OFF`，首页短按切换 ON/OFF；独立返回键退出。开关仅保存在本次运行的 RAM，重启恢复 OFF，不修改用户存档。
- 开启后，新发送的频道文字和好友定向文字可由开启中继的同版设备转发。自动发现同频道的直连节点，不需要给中继设备加好友；私信最终接收者仍按原有好友规则验收。
- 转动查看转发计数、去重和丢弃计数，以及节点昵称、MAC、RSSI、最后听到的时间。最多记录 16 个直连节点，15 秒未听到就不再显示。
- `HEARD n HOPS` 是最近听到的合格文字包元数据，不等于确认送达，也不是距离。频道广播的 Sent 只表示本机发出；好友私信只有收到目标回执才显示 Peer received。
- 网络页是直连邻居表和统计页，**不是完整拓扑图**，不推断未观察到的设备连线。单台设备显示 DIRECT PEERS 0 是正常现象。

## 转发范围与保护

只转发明确带中继标志的文字消息（QUICK/MORSE）和回执；实时摩斯字符、配对、石头剪刀布、宠物联机、寻宝和多人游戏不转发。HID/扫描等独占无线工具暂停通信时，中继也暂停。

源节点计作第一跳，最多三条无线链路（A→B→C→D）。中间节点保留原始源/目标、会话和消息编号，仅增加转发次数并重算 CRC。每节点 8 条待发队列、64 条去重记录；80–240 ms 随机退避，最多每 250 ms 取出一个中继包，排队超过 3 秒丢弃。本地消息、实时字符与控制包优先于中继和发现信标。

同一消息的连续广播在 1.8 秒窗口内去重；允许后续发送重试再次穿过中继，避免首次接收保存失败或回执丢失后永远无法恢复。路由私信采用 3 秒回执等待，保留原四次发送上限；拥塞时仍可能失败，不承诺必达。关闭开关或切换频道会清理待转发数据；发现信标约 5 秒一次且不转发。

## 兼容与隐私

沿用 v3 包长度，利用原保留 flags 位表示中继标志和转发次数，追加 discovery 类型 14。旧固件不认识这些标志，会拒绝中继消息；演示时所有设备必须升级同一版本。关闭网络后新发文字仍使用原直连格式。不能把“头部长度未变”说成新旧版本完全兼容。

保留原好友检查、消息去重、入箱保存成功后再回执的语义，不更改 NVS v7/storage ABI 1、宠物和草稿格式。中继队列和邻居表不落盘，也不上传云端。

**CRC 不提供身份认证或加密。** 开启网络会广播设备昵称，附近开启的节点可能看到转发的明文。请勿发送密码、隐私内容；这是教学实验，不适合应急通信或安全保证。没有实现路由认证、抗恶意节点、完整拓扑、离线存储转发或互联网远程聊天。

## 三台设备如何验收

1. A、B、C 全部更新同版，打开网络、设置相同频道；私信先让 A/C 成为好友。
2. 实际隔离 A/C 射频直连，保留 A↔B、B↔C。仅凭低 RSSI 不能证明隔离。
3. 关闭 B 中继，确认 A→C 收不到；开启 B，再用不同消息验证 C 收到且同一消息不重复入箱。C 的 HEARD 2 HOPS 与 B 转发计数是辅助证据。
4. 私信检查 A 收到目标 C 的回执；断开 B 再验证失败，再接回验证重发。广播不要求每人回执。
5. 用第四台设备验证三跳上限、替代中继的可达性；本实现无固定路由表，不称为最短路径或最优路径切换。

主机测试 `tools/test_mesh_route.c` 使用生产包编解码和转发核心，模拟 A-B-C 及反向回执、最大消息、跳数、去重/重试、限流、队列过期、节点发现和时间环绕。`tools/test_network_ui.py` 检查页面边界和操作。它们不证明真实射频多跳成功；COM9 单机只能验证启动、开关、界面和无邻居状态。
