# 2 MiB 主程序槽与 USB 分区迁移

2026-10-23 用户批准扩大主程序槽，实机目标 COM9。目的：保留游戏和宠物功能，容纳后续带证书校验的 HTTPS 上传，不通过关闭证书校验节省空间。

## 布局

| 分区 | 原地址 / 大小 | 新地址 / 大小 |
|---|---|---|
| nvs | 0x9000 / 0x6000 | 不变 |
| otadata | 0xf000 / 0x2000 | 不变，迁移时清除旧 OTA 启动选择 |
| phy_init | 0x11000 / 0x1000 | 不变 |
| factory | 0x20000 / 0x130000 | 0x20000 / 0x200000（2 MiB） |
| ota_0、ota_1 | 原来的两个应用槽 | 移除，不再作为应用槽使用 |
| nvs_sec | 0x3b0000 / 0x6000 | 不变 |

0x220000–0x3affff 暂不分配。保留两个 NVS 分区的物理地址和大小，NVS v7 与存档 ABI 1 不改。新布局标识 `factory-2m-usb-v1`。

**这是 USB 更新的单应用布局，不是双槽 OTA。** 不能使用旧三槽 OTA 镜像/升级流程，也不能向尚未迁移的设备单独刷入超过旧槽的应用。

## 工具与防护

- `tools/flash_layout.py`：校验二进制分区表 MD5，并匹配完整已知布局；NVS 地址或大小有变化即拒绝。
- `tools/build.py`：从实际生成的分区表读取容量，不再把旧槽大小写死；manifest 记录布局、实际余量和迁移要求。
- `tools/verify.py`：核对镜像哈希、源码快照、实际分区容量与 manifest 一致性。
- `tools/flash_backup.py`：核对 ESP32-C6 / 4 MiB / 指定 MAC；同一下载会话连续读取两遍完整 Flash，比较全部字节并做落盘验证。
- `tools/flash_migrate.py`：默认只显示计划，必须加 `--apply` 才写。操作前现场重新双读备份；核对旧布局、设备身份、发布产物、原 bootloader 与新包一致。禁止安全启动/Flash 加密设备套用这个流程。

迁移不擦除整片 Flash，不写 bootloader，不主动写两个 NVS。保持设备停留在下载程序中，依次写应用、otadata、分区表，分区表最后写；随后读取完整 Flash，核对每份写入镜像，并逐字节比较所有允许范围以外的内容。写入失败时不自动启动未验证应用。

完整 Flash 备份位于本地 `build/migration-private/`，**可能含 Wi-Fi 密码、私信、设备凭证等，不能上传 GitHub或发给他人。** 整个 build 目录已忽略。普通公开文档只记录结果，不包含备份内容。

## 执行原则

1. 先退出游戏并保存；确认只有目标设备占用指定串口，保持 USB 电源稳定。
2. 先只读备份，再完成新分区编译和验证。
3. 先检查迁移前 UI，再运行迁移工具；不要绕过身份、分区或备份检查。
4. 成功写入后先做回读校验，再复位检查宠物和两个游戏的存档/纪录菜单。
5. 备份留到实际使用确认稳定后。以后在已迁移设备上通常只更新 0x20000 的应用；新旧布局不可混用。

命令示例（以实际确认的串口、MAC 和 ESP-IDF 5.5.4 Python 运行）：

```text
python tools/flash_backup.py --port COM9 --expect-mac <设备MAC>
python tools/test_flash_layout.py
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1
python tools/verify.py
python tools/flash_migrate.py --port COM9 --expect-mac <设备MAC>
python tools/flash_migrate.py --port COM9 --expect-mac <设备MAC> --apply
```

工具只接受已知旧三槽布局迁移；检测到已迁移设备会拒绝重复执行，避免把正常更新误当分区迁移。

## 恢复与限制

默认拒绝替换不同的 bootloader。只有获得用户针对目标设备的明确授权后，才可额外指定 `--replace-bootloader --apply`：仍须双读整片备份、核对芯片身份与安全状态，并验证配套发布包；bootloader 必须完全位于 0x0000–0x7fff，写入顺序为应用、otadata、bootloader、最后分区表。回读校验包括 bootloader，允许修改范围只额外增加其占用的 Flash 扇区，两处 NVS 仍须逐字节保持不变。此操作不能套用于加密或安全启动设备。

分区调整不是原子更新，不具备 OTA 的断电回滚保证。刷写中断可导致无法启动，但不主动更改 ROM 下载能力；应保留 USB 下载路径和本机私有完整备份。

需要恢复时，先确认设备 MAC、备份长度为 0x400000、两份备份一致且 SHA-256 与本地记录一致，再制定恢复操作。完整备份恢复会覆盖整片 Flash、回到备份时的旧分区和数据，并丢弃备份后新增的数据；**不要将其他设备的完整备份刷过来，不要随意执行全片擦除。** 此文档不自动触发恢复。

宿主的布局/写入范围校验测试不等于实机断电试验。未测试 Flash 加密、Secure Boot、迁移中拔线和每一种故障恢复路径。
