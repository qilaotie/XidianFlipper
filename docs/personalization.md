# 首页、系统皮肤和宠物房间

2026-10-23 当前 main 源码。重新构建的镜像在 `build/release`；旧冻结发布包不包含本轮功能。

## 首页小组件

进入设置，找到“首页 / Home”，短按依次切换：消息、宠物、游戏纪录、自动轮播。立即生效，重启保留。

- 消息：沿用原来的信封和未读提醒。
- 宠物：显示宠物名字、简化头像和状态。F 为饱食、E 为精力；另一行轮换为 M 心情、C 清洁；G 为金币。
- 游戏纪录：T 为俄罗斯方块最高分，S 为贪吃蛇最高分；蛇的 LEN 最长长度与分数交替显示。没有纪录显示 `--`。仅查看纪录，不开局、不领取金币。
- 自动：以上三种内容每 8 秒切换。非消息组件仍在顶部显示未读数量。

## 三套系统皮肤

设置中的“皮肤 / Skin”，短按循环选择：

| 皮肤 | 外观 |
| --- | --- |
| 经典像素 PIXEL | 原有像素图标、反白选中条 |
| 极简线框 MINIMAL | 线描图标、轮廓选中框、虚线分隔 |
| 终端风格 TERMINAL | 字符卡片图标、光标式选中条、双线分隔 |

主要影响首页、主菜单与列表；不反转滚轮，不改游戏操作，也不替换游戏画面。中英文选择独立保存。

## 宠物房间

进入“趣玩 → 宠物”，旋转到 `ROOM`，短按进入。旋转预览，短按购买并装备，BACK 退出。预览不花钱。

| 房间 | 一次性价格 | 内容 |
| --- | --- | --- |
| CLASSIC 原房间 | 免费 | 原有背景 |
| STUDY 书房 | 25G | 窗户、书架、地板 |
| GARDEN 花园 | 35G | 太阳、云、草地 |
| SPACE 太空 | 50G | 星星、月亮、舱室地板 |

购买后可免费反复装备；余额不足不扣币。原有盆栽、星饰、地毯仍从背包装备，与房间背景叠加。房间所有权和选择在重启、重新养蛋后保留。

`ROOM EQUIPPED` 表示已装备；`WAIT` 或存储错误时先稍等重试。出现 `SAVE ERROR` 时不要立刻断电，等待成功保存。快速连续操作受原有宠物操作冷却限制。

## 更多待机动作

在宠物主页自然等待，可看到打哈欠、挠头、侧看、小跳、摆尾；心情较好时会跳舞，拥有球时会玩球。睡着或精力低时不做剧烈动作。这些是外观表现，不额外扣精力、加金币或频繁写存档。

## 存档兼容边界

旧宠物记录可直接读取，不清空名字、年龄、金币或物品。房间所有权和当前房间使用宠物 `state_v2` 的两个原保留字节，与钱包放在同一个 NVS blob 中提交，不新增钱包分离写入。宠物记录仍为 28 字节，全局 NVS 版本和分区地址不变。

**购买新房间后不要直接降级到不认识房间字段的旧固件。** 旧验证器要求这两个字节为零，会拒绝新记录；如需降级，应先做完整私人备份并使用兼容迁移方案。不要清空 NVS 来“修复”。系统外观另存于 `ui_personal/style_v1`，不占用语言开关的记录。

## 验证

宿主测试覆盖：外观组合重启保持、失败提交保留旧选择、未知记录不覆盖；房间预览零扣费、购买一次扣费、重新装备免费及重启保留；动画绘图边界；首页极值文字边界、纪录只读和轮播。实机界面验证使用 `tools/smoke_personalization.py`，只预览房间，不替用户花金币。

### 联网重启的附带排查

首次实机验收中发现后台云同步触发任务看门狗。解码对应 ELF 后，首次调用栈位于 TLS ECDH 的硬件 MPI 等待路径；临时切换软件 MPI 后，仍在证书签名运算中触发。因此不能认定硬件初始化死锁：共同问题是优先级为 2 的长时间 TLS 计算饿死了被看门狗监视的空闲任务。

最终保留默认硬件加速，把 `cloud_sync` 工作任务降到优先级 0，利用 FreeRTOS 时间片与空闲任务公平运行。不修改共享 SDK、不关闭证书验证或看门狗，不改变云端协议，也不增加看门狗超时。两次定位日志留在忽略的私人 build 目录，不随源码分享。
