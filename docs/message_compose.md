# 自定义文字消息

当前源码支持表情插入、重启后继续编辑、六槽草稿箱及常用消息复用。

入口：`Messages → Write message`。

### 编辑用途

只有普通写消息、回复使用 `SEND` 并进入收件人选择或回复确认。
群聊、公告、离线/代存留言的文字编辑使用 `DONE`，确认后返回原来的预览页，再通过该功能的发送按钮操作。
队伍名称、加入码、昵称、签名、投票和活动标题使用独立内容编辑区，显示 `DONE`，没有发送、收件人或草稿箱入口，也不会覆盖消息草稿。
内容编辑长按只是选中 `DONE`，短按确认；字符组内返回到选组，选组处返回取消本次修改。长度上限随用途变化（例如昵称 12、加入码 8、投票 48）。

- 第一层依次是：`ABC` 大写、`abc` 小写、`123` 数字、`SYM` 标点、`SPACE` 空格、`DELETE` 删除、`SEND` 发送、`EMOTES` 字符表情、`SAVE` 保存槽位、`DRAFTS` 草稿箱、`NEW` 清空编辑区。
- 进入组后旋转选择字符，短按输入，可连续输入。每组记住上次选择的位置。
- 空格、删除、发送都是一级操作，选中后短按立即执行，不再进入 EDIT 二级菜单。输入空格和删除后仍停在第一层，便于连续操作。
- 长按：跳到 `SEND`，再短按进入收件人选择；不会仅因长按就发出消息。
- 收件人第一项是当前频道，也可选择好友。短按收件人发送，随后显示发送状态。
- BACK：组内返回选组，选组时再按会保存当前工作草稿并退出编辑；不会自动清空已发送的草稿，方便修改重发。保存失败会停留并提示。

最多 128 个可打印 ASCII 字符。正常退出编辑后重启可恢复；尚未保存就突然断电的修改可能丢失。快捷短语不会覆盖编辑草稿。
第一行显示草稿末尾 20 个字符，第二行显示当前组、字符和长度。各组和组内字符都可首尾循环；`SYM` 保留全部 32 个 ASCII 标点。

这不是运营商短信：消息通过既有 BLE 电台协议发送，不需要 SIM 卡，也不会发送到手机号。此版没有中文输入法或完整中文字库。

## 字符表情

从编辑器第一层的 `EMOTES` 或 `Messages → ASCII faces` 打开表情分类，再选择具体表情。共 **48 个**，分 6 类，每类 8 个：`Happy / cheer` 开心、`Sad / tired` 难过疲惫、`Surprise / shock` 惊讶、`Love / hello` 互动问候、`Reactions` 反应、`Animals` 动物。所有表情都只使用可打印 ASCII，新增表情不需要新中文字库。

例如：`\(^o^)/`、`o(^_^)o`、`<(^_^)>`、`(^-^)/`、`(=^.^=)`、`(U^_^U)`、`(o'_'o)`、`(\_/)`。编辑器中选定后追加到消息末尾并直接返回编辑器；从消息菜单独立进入时仍可选好友或频道单独发送。BACK 从具体列表返回分类，再返回原入口，不改变草稿。

编辑器插入表情不会进入发送流程；消息菜单里的独立表情使用单独发送缓冲区，不改变当前草稿。发送仍须选择收件人。

宿主逻辑测试：`gcc -std=c11 -Wall -Wextra -Werror -fno-stack-protector -I firmware/ui tools/test_message_draft.c -o build/test_message_draft.exe`，然后运行生成的程序。

## 表情插入与持久草稿箱

- 编辑器的 `EMOTES` 打开表情列表，选中后将完整字符表情追加到当前消息末尾，并返回编辑器。超过 128 字符时不插入、不截断、不进入发送流程。消息菜单里的独立“字符表情”仍可单独发送。
- `消息 → 草稿箱` 提供 6 个保存槽，每槽最多 128 个可打印 ASCII 字符。槽位显示编号和前 20 字符预览，短按后可编辑副本或删除。
- 编辑器组列表保留 ABC / abc / 123 / SYM / SPACE / DELETE / SEND / EMOTES，新增 `SAVE`（选择槽位保存或覆盖）、`DRAFTS`（打开草稿箱）、`NEW`（清空当前编辑区）。字符输入和用户消息不汉化。
- `SAVE` 后选择已有槽位必须确认覆盖；删除、清空编辑区，以及加载不同内容替换当前消息都先停在“取消”。保存失败不改变旧槽位，加载失败不丢弃当前文字。读取损坏或未来版本存储时不会静默覆盖原记录。
- 从字符组 BACK 只返回组选单；从组选单 BACK 离开时保存当前编辑草稿。SEND 和打开草稿箱前也保存当前内容；发送后不清空当前草稿或已存槽位。每打一个字不写 Flash，重复保存相同内容不写入。突然掉电前尚未保存的修改不能保证恢复。
- 常用消息操作：编辑 → SAVE → 选择槽位 → 以后在草稿箱选择该槽 → 编辑 → SEND；修改常用消息后再次 SAVE 并选择同一槽确认覆盖。只加载、发送不会自动覆盖原模板。
- 草稿保存在本机 NVS 独立 `msg_drafts/drafts_v1`，不修改 NVS 全局版本、分区或消息协议，不上传云端。恢复出厂会清空，普通重启保留；它不是完整历史消息备份。

## 验证

主机测试：`tools/test_message_draft.c`、`tools/test_draft_store.py`、`tools/test_draft_ui.py`。覆盖表情容量边界、六槽持久化、失败/损坏记录保护、确认取消、编辑器祖先页面复用等；这些不是实机掉电故障注入。

COM9 已烧入并回读校验草稿箱初版，升级前后分区表与两处 NVS 保持不变。通过机身等效 USB 输入创建 `Hi (^_^)`、存入第六槽，硬复位后确认当前工作草稿和槽位均保留，再加载编辑、确认清空及删除测试槽，最后回首页。没有发送消息、操作其他用户草稿或修改宠物。私有日志与截图仅留在忽略的 `build/draft-smoke/`。
