# 队伍、代存留言、旅行护照、合奏与资料卡

COM9、COM10、COM15 已统一更新；实机证据与边界见[三机验收记录](social_three_validation.md)。

本轮实验功能面向同版 ESP32-C6，中文开关沿用设置中的“中文界面”。消息 → 队伍与社交、工具 → 队伍与社交是总入口；趣玩另有合奏、旅行护照入口，宠物主页末尾也可打开护照。不需要互联网；先在工具开启自组网。旧固件不能识别新帧，参与设备须统一更新。

## 中继代存留言

发送端在“队伍与社交 → 中继代存留言 → 用草稿发代存留言”选择好友并确认。确认页明确说明明文会交给中继，最多128个 ASCII 字符。仍使用原六槽发送端发件箱，但新增可代存标志；普通离线留言不会自动变成可代存留言。

中间设备需要主动开启自组网和“代存”开关。默认两者重启均关闭。中继最多持久保存四条其他设备的可代存留言，满了不挤掉已有条目。写入成功后才安排转交；源设备离开后，缓存仍可用。中继重启后要手动重新开启两个开关，原缓存和尝试预算保留。

只有目标设备保存消息后发出的真实回执才代表送达，中继收到缓存不会伪造“已送达”。中继保存真实回执的身份摘要，发送者回来以原身份重试时，可以重放该回执。回执去重/取消表最多八项，不能无限期保存所有历史。留言原始源/目标 MAC、启动会话和消息 ID 不变，转发仍受三段链路限制，不重置跳数来无限传播。

每条最多尝试120次，约每30秒重试，所有代存发送间隔至少10秒。另有30分钟累计启用时间预算，按分钟持久扣除；关机/关闭网络时间不计，重启可能损失不足一分钟的计时精度，但不会重置已用发送次数。这里不是可靠的日历到期时间，不能把断电一天当成已经自动清理一天。

取消本机发件箱会尝试广播取消标记（需要自组网开启），收到取消的中继移除相应缓存；取消不保证到达所有离线中继，已送达的消息不会被收回。中继也能确认删除自己的单个副本，这不取消其他副本。敏感内容不适合交中继：CRC 和设备地址不认证身份，消息为明文。

## 队伍／房间

“队伍与房间”可用工作草稿作为队名创建队伍（1～18个字符），显示八位十六进制加入码；其他设备将该代码输入草稿，通过“用草稿八位代码加入”。加入者还需选择相同频道。加入码不是密码，不能提供加密或防冒充。

当前房间会隔离普通文字群聊、投票、任务板、签到、抢答、资料卡和合奏的接收与参与。长任务板采用有界双片重组，不截断126字节状态。群聊最多123字符，为房间标识留出空间；普通好友私信、代存留言、全网公告、摩斯实时输入及原有直连宠物/游戏不纳入房间隔离。全网公告仍有意跨频道，因此不是队伍秘密消息。

更换/离开房间结束当前实时协作会话；旧房间排队帧不会被当成新房间操作。房间代码和名称会保存，但重启不会自动加入，需选择“重新加入已存队伍”。旧收件箱记录沿用原格式，不保存历史房间 ID，不能按旧房间完整恢复聊天记录。在线成员表最多八台，基于最近成员广播，不保证每台此刻仍在线。

## 个人资料卡

当前收件箱只记频道，不记历史队伍 ID。回复队伍消息前应重新加入原队伍，或选择好友私信；在其他队伍/公共空间确认频道回复，会按当前空间发送。

可用工作草稿设置独立昵称（最多12字符）、签名（最多24字符），并复制当前宠物名字。它不会改写旧好友名单里的昵称，也不会随宠物改名自动同步，需要再次复制。默认不分享，用户打开“资料卡分享”后，自组网开启时约每10秒发送到当前房间/公共空间。重启或更换/离开房间会关闭有效分享，需在新空间主动重新开启，避免原房间的资料自动发到公共空间。

最多缓存八个附近成员或资料卡，过期后不再列出/显示；离开房间、重启会清空缓存。开启队伍会广播成员身份及昵称；未分享时不会广播签名和宠物名。分享关闭后，别人已有的短时缓存可能仍显示一会儿，不是远程擦除。

## 宠物旅行护照

先正常照顾宠物，使它可以玩耍；未起名设备由用户自己命名后再拜访。拜访协议沿用最多七个显示字符，因此印章中的对方名字可能截短。

正常完成一次联机宠物拜访，双方各保存一枚对方设备的旅行印章；对战不发印章。记录对方宠物名、设备尾号和成功拜访次数，同一轮重复结算不重复加次数。没有额外金币奖励，也没有模拟拜访来获取印章。

护照独立保存，不更改宠物旧存档；最多十二台不同设备，满了不覆盖旧印章。同一设备换宠物仍归入同一印章，次数继续增加；它是本机的旅行日志，不是跨设备的宠物唯一身份系统。改名、孵新蛋不会自动清除护照。

## 多设备灯光与蜂鸣器合奏

各台主动打开合奏页才监听；退出页面停止监听和本页拥有的声音，监听60秒后需重新开启。声部1为主旋律、2为低音、3为短节拍、4仅灯光，支持三段简单曲目及90/120/150 BPM。主持端点击开始，约1.5秒后发送十六拍；各台可看到接收到的拍数。

遵守设备声音、灯光开关，蜂鸣频率保持现有驱动2～6 kHz范围。遇到其他声音占用时不强行覆盖；旧页面退出也不会停止后来启动的其他声音。这里是按接收到的拍子触发的近似合奏，不是精确时钟同步；无线延迟或丢包会造成错拍/漏拍，不补播已经过时的拍子。

## 存储与测试

代存使用独立 `relay_mail/cache_v1`，资料卡、记住的房间和护照使用 `social_user/social_v1`；NVS v7、storage ABI 1、原消息和宠物结构不变。损坏或未来版本不自动格式化。正常写失败保留旧内存/存档，不宣称保存成功。供电中断一致性仍需专门硬件验收。

主机测试入口：`tools/test_personal_network.py`；原有网络接收、路由、发件箱、宠物联机、汉化和菜单也需回归。实机工具 `tools/smoke_social_three.py` 分阶段验证，USB只模拟正常输入和读取屏幕，不注入帧或存档。真正代存应证明目标离线时缓存、源离线后由中继独立转交，以及目标再次离线后源可收到保存的真实回执；不能用三台同时在线直接收到消息来冒充这个结果。
