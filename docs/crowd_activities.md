# 多人签到、抢答、网络诊断和活动记录

COM9 / COM10 已更新并完成双机实测，结果与限制见[验收记录](crowd_two_validation.md)。

参与设备需要更新到同版，在相同频道开启“工具 → 自组网状态”。无线收发和活动不需要互联网。中文开关沿用“设置 → 中文界面”，关闭后恢复英文；题目、任务、用户消息和昵称保持用户原文，没有新增中文输入法。

## 多人签到

消息 → 多人签到 → 发起多人签到。使用工作草稿编辑主题（1～32 个英文、数字或符号），预览后确认创建。活动创建前可以取消，不发送任何请求。

参与设备进入多人签到，选择“我已到达 / 我在路上 / 我不参加”。主持端确认后更新名单，同一设备改选会更新原条目，不重复计人数。最多八个设备标识，主持人也可以签到。主持端通过“结束签到”确认关闭，结束后的汇总写入活动记录。

## 联机抢答器

消息 → 联机抢答器 → 开放新一轮抢答。编辑本轮主题并确认后，主持端开始接收抢答；参与者进入同页，将滚轮选到“现在抢答”，短按提交。

主持端最先收到的有效请求成为本轮唯一胜者，随即关闭本轮并广播结果。主持人也能抢答；其他请求被拒绝。重复包不会另产生胜者，旧轮次请求不能进入新一轮。主持人可取消尚未产生胜者的轮次，或用相同主题开放新一轮。

这是按主持端收到请求的顺序判定的趣味抢答，不是同步计时仪器；无线重试、转发与菜单操作可能影响到达顺序。没有按键毫秒反应速度排名，也没有虚构各设备统一时间。

## 网络诊断

“工具 → 网络诊断”或“消息 → 网络诊断”可以查看：

- 当前频道、15 秒内直连设备数、最近收到的路由帧跳数。
- 实际转发完成数、重复帧抑制数、转发丢弃数、接收队列丢弃数。
- 文字发送完成数、收到的目标回执、已接受或拒绝的文字消息。
- 最近投票/任务及签到/抢答操作的确认等待毫秒数、有效确认数、重发数、超时数。
- 活动记录数量、保存错误以及进入自组网设置的入口。

确认耗时从本地提交操作开始，到主持端确认到达为止，包含排队、无线、主持端处理与可能的重试。只统计远端操作确认，本机主持本机操作不生成无线耗时。没有确认时初始数值为零；确认数也为零。诊断计数重启清零，不显示完整拓扑，不把广播发出当作全员收到。网络暂停期间会明确显示附近通信已暂停。

## 活动记录

消息 → 活动记录，保存最近 12 条结果摘要，按新到旧排列，超过上限替换最旧记录。包括结束的投票票数、完成的任务及领取者、结束的签到人数汇总，以及抢答胜者或取消结果。参与设备只有收到结束状态后才能记入，不会补造没听到的结果。

记录包含主题、频道、主持设备尾号、当地记录序号和保存时本次开机秒数；没有可靠日历时间时，不伪造日期。详情页进入后正常转动可查看各项。实时活动仍是 RAM 会话，重启/切频道会结束，但已成功保存的结果保留。

记录使用独立 NVS 命名空间 `activity_log/history_v1`，不修改 NVS v7 或 storage ABI 1。相同结果重复广播不重复落盘；周期状态广播不周期写 Flash。写入失败不替换 RAM 中的旧记录，诊断页提示保存错误，当前还保留的结束状态隔十秒重试。损坏、截断或未来版本的数据保留，不自动格式化。意外断电恢复尚未做硬件验证，不能承诺刚发生的结果一定已保存。

## 本轮补齐的汉化

补齐消息管理、筛选与回复/删除确认、投票、任务板、联系人状态、自组网状态、群聊、公告、离线留言及发件箱，以及本轮签到、抢答、诊断和活动记录的菜单、动态状态、数字格式与错误提示。使用新增字形的子集字库，没有引入完整中文字库。消息编辑器、用户主题和无线昵称保持原文。

## 协议与后续计划

沿用实验性 v3 COLLAB（类型 15），签到操作码 7～9，抢答 10～12，最多三段链路，同频道转发。每种活动同时发现一个主持端，主持端超过 15 秒未更新才允许其他主持端替代；同一主持端的新轮次立即同步，旧轮次回放不回退当前轮次。请求确认带有主持会话、活动标识、请求者启动会话及序号，最多六次发送、八秒等待；无确认表示结果未知。设备标识/CRC 不提供认证。

中继代存留言仍是后续开发项：当前只有发送端持久离线发件箱和短时中继转发，尚未让中间设备持久保存他人留言。后续需单独设计配额、过期、重启去重、回执归属和取消传播，并用三台设备验证，不把现有发送端发件箱冒充中继代存。
