# COM9 / COM10 实时协作验证（2026-10-27）

固件：ESP-IDF 5.5.4 / ESP32-C6，应用 1,608,720 字节，剩余 488,432 字节。SHA-256：`68d020ac809dfdecca7c29a9a71ac380623ed27190262a5ef00321149af33e9c`。

两台均通过设备身份和现有 2 MiB 分区核对、应用双读备份、app-only 写入与完整回读；写入前后分区表及两处 NVS 校验一致。

实测使用真实 BLE 射频，USB 只模拟正常滚轮/按键并读取屏幕。没有注入协议帧、修改存档或绕过业务状态机。

1. 同频道开启 MESH，两台好友状态均显示 15 秒内直接听到。
2. COM9 编辑测试草稿 `TEAM`，创建二选项投票；COM10 发现同一投票，投 B；COM9 投 A。COM9 显示 A=1/B=1，COM10 显示 B=1。
3. COM9 以 `TEAM` 创建任务板，COM10 发现 OPEN 任务并领取、完成；COM9 收到并显示 `[DONE] TEAM`。
4. COM9 打开消息管理、筛选收件箱、长按消息进入操作，选择引用，编辑器出现 `>FEE0:QO01 | TEAM`，保留已有草稿。没有发送引用回复，以免给 COM10 已满的收件箱挤出旧消息。
5. 使用编辑器 NEW 确认清空测试草稿，两台返回首页。正常运行期间没有观察到重启、断言或看门狗报告。
6. 测后再次双读两处 NVS：两台频道仍为 1，工作草稿为空、离线发件箱为空；好友、收件箱内容及常用草稿与测试前一致。COM9 收件箱仍 21 条，COM10 仍 32 条。NVS 中只有宠物自动随时间更新的 `pet_user/state_v2` 和 `extra_v1` 发生变化，未重置宠物。只读检查后正常复位，结束临时活动，MESH 回到默认关闭。

主机测试另外覆盖：真实协作核心的丢确认重试/去重、重复投票拒绝、两个领取者竞争、非领取者完成拒绝、过期板版本拒绝、频道切换清空、确认超时及联系人观测衰减；消息引用的保存失败/溢出与原草稿保护、私信/频道回复和取消保护。原有草稿编辑、网络操作、网络页面、持久发件箱、菜单布局和路由测试回归通过，构建清单验证通过。

尚未实机验证八台同时投票、四任务并发争抢或第三台中继；单条删除的存档操作与回复发送没有在用户旧消息上做破坏性实测。不要把主机模拟覆盖表述成这些射频情境通过。会话不保证断电恢复。
