# 一藏多找与多人反应赛

参与设备需要包含相应功能的固件，入口在 `FUN` 的附近互动游戏组。多人反应赛使用新版 v2 游戏协议，不与旧双人反应对决互通，所有参赛设备都要更新。

## Treasure radar

默认是寻找模式。旋转旋钮切换 `HIDING`（宝藏端）和寻找端。一台留在 HIDING 页面，放在待寻找的位置；多台寻找端可以同时接收同一台宝藏的广播，各自显示昵称、RSSI 和信号格数，无需配对，也不占用独享连接。

寻找端默认跟随当前信号最强的宝藏。短按锁定/解锁当前目标，锁定标记为 `*`。长按启用/关闭提示音，信号越强提示越密；声音仍受设备既有静音设置控制。3 秒未收到目标广播显示丢失，不继续使用旧信号提示。

RSSI 仅供冷热参考，墙壁、人体遮挡和设备朝向会影响读数。不是方向雷达，也不提供米数；只寻找主动打开 HIDING 的设备，不是追踪任意蓝牙设备。

提示音为 30 毫秒的独立短滴声，间隔随平滑后的 RSSI 连续变化：-95 dBm 为 2500 ms、-65 为 1000 ms、-50 为 500 ms、-40 为 260 ms、-30 为 120 ms、-25 及更强为 80 ms（约每秒 12.5 次）。不再跟随屏幕格数提前饱和；全局静音、提示音开关和目标丢失仍优先。

## Reaction party（2–4 人）

一台选择 `CREATE ROOM` 创建房间，其余选择 `JOIN ROOM` 加入发现的可用房间。房主也计入 4 人上限。大厅转动旋钮可以查看玩家昵称和准备状态。

每位玩家按下并松开旋钮才算准备好，再按可取消准备。至少 2 人、所有人准备好，并连续 5 秒没有新人加入后，房主锁定名单；新人加入、取消准备、成员离开会重置倒计时。锁定后要收到所有成员的名单确认才会开赛，迟到者不能插入本轮。

正式开赛后，各机独立等待随机 2–5 秒，看到自己屏幕上的 `GO` 立即按旋钮。不是所有设备同时亮屏：本机测量反应时间，房主只汇总成绩，避免把无线传输时间算进成绩。

- 采用按下沿原始时间戳，而不是短按释放时间。
- 正式开赛后、GO 前按下为抢按；10 秒内未按为 `DNF`，大厅里按键只切换准备状态。
- 转旋钮查看所有人成绩和名次；同分同名次，后续名次跳号。抢按或 DNF 不参与有效名次。
- 成绩页每人按一下表示下一局，全部仍在线成员同意后回到新一轮大厅，重新准备并重新等 5 秒。
- 大厅 6 秒无心跳的成员被移除；名单确认超时则取消本轮、退回大厅重新准备；比赛中掉线按 DNF（已提交成绩保留）。
- 客户端 8 秒收不到房主快照就显示房间丢失，不会中途选举新房主；BACK 随时退出。
- 房间、每局轮次、设备会话 token 和递增序号隔离旧包，成绩首次提交后锁定；广播周期有随机抖动以减少同步碰撞。

这是娱乐测试，不是专业计时仪器：屏幕刷新和输入消抖仍有误差。BLE 广播游戏不具备密码学防作弊，适合可信设备间使用。

## 验证

`gcc -std=c11 -Wall -Wextra -Werror -Wno-error=sign-compare -fno-stack-protector -I firmware/protocol tools/test_nearby.c firmware/protocol/mesh_packet.c -o build/test_nearby.exe`

`sign-compare` 例外仅用于既有协议文件在 64 位宿主编译器上的比较警告；其余警告仍按错误处理。

运行 `build/test_nearby.exe`。雷达宿主测试检查同一广播被三个独立寻找端接收、锁定/过期、声音频率/静音和队列边界。

将上述命令的源文件改为 `tools/test_party.c`、输出改为 `build/test_party.exe` 并运行，可测试四个独立生产状态实例，以及第五个迟到的加入者：5 秒门槛、新人/取消准备重置、名单确认、丢包重传、排行并列、下一轮、旧包、抢按/DNF 和房主掉线。这些是宿主模拟，不是四台设备射频实测。

`python tools/smoke_party.py --host COM9 --join COM10` 保存双机实测屏幕和日志到 `build/party-smoke`。脚本只自动确认页面导航与无崩溃，成绩/人数和下一局结果需查看截图确认。

### 2026-10-20 双机验收

COM9、COM10 已更新同一版固件，写入哈希校验通过。人工查看保存的 OLED 帧确认：一台创建、一台加入；双方显示 2/4 人和 2 人准备，均出现自动开赛倒计时；成绩榜在两台上显示一致的玩家成绩；转动可查看另一人成绩；双方确认下一局后回到 2/4 人、0 人准备的大厅。脚本按键用于验证通信与流程，不代表真人反应时间或专业计时精度。四人场景当前仅完成宿主模拟，尚未做四台射频实测。
