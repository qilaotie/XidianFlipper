# 电子宠物：轻量养成

本页保留 v1 的原始说明与验收记录。当前已扩展四阶段成长、三种成年分支、金币、商店、背包、装饰和图鉴，操作与迁移以 [电子宠物 v2](pet_v2.md) 为准。

入口：`FUN > Pet`，横屏显示。左侧是宠物，右侧是状态、当前照顾动作和提示。

## 操作

- 旋转选择 FEED（喂食）、PLAY（玩耍）、CLEAN（清洁）、SLEEP（睡觉）。
- 短按执行，至少间隔 2 秒，避免连续误触。
- 睡着时 SLEEP 改为 WAKE，选择并短按唤醒。睡眠中不能喂食、玩耍或清洁。
- 长按切换详细数值和普通状态：FOOD 饱腹、MOOD 心情、REST 体力、WASH 清洁，都是 0–100，越高越好。
- BACK 保存并返回。没有重置宠物的快捷键，防止误删成长记录。

## 成长与照顾

新宠物为蛋，累计开机 60 秒孵化成幼体，1800 秒（30 分钟）变成成体。左上阶段显示 EGG、BABY、ADULT 和累计开机分钟。蛋期间暂不能照顾，倒计时等待孵化。

保持开机时，即使在其他菜单或关屏也会继续成长。完全断电或进入深睡后暂停成长，不计算离线时长。宠物睡觉是游戏状态，设备仍然开机，宠物会继续成长和恢复体力。

每分钟：清洁和心情各减 1，饱腹清醒减 2/睡觉减 1，体力清醒减 2/睡觉加 8。饱腹或清洁过低时心情额外下降。喂食加 20 饱腹、3 心情；玩耍耗 8 体力、3 饱腹，加 15 心情；清洁恢复到 100 并加 3 心情。体力不足不能玩耍。

有待机起伏、眨眼、睡觉 Z、喂食小点/清洁泡泡/玩耍动作。状态太差会出现不高兴、脏污和 HUNGRY、TIRED、NEED WASH 提示，但不会死亡。没有联网、复杂进化树或宠物间对战。

## 存档

独立 NVS 命名空间 `pet_user/state`，版本 1，不改全局 NVS v7、好友/消息/网络存储或分区。NVS 自带完整性保护，另验证版本、记录长度和属性范围。遇到未知/损坏记录显示 SAVE ERROR，不静默覆盖原记录。

照顾动作合并写入，正常最多等待约 5 秒，显示 SAVING 时还未提交；后台成长每约 60 秒保存一次。退出宠物页和进入深睡前尝试立即保存。直接断电可能丢失最近数秒照顾或一分钟内的成长，不承诺每帧实时落盘。保存失败显示 SAVE ERROR 并有限频率重试。

## 验证

- `tools/test_pet.c`：蛋/幼体/成体边界、动作、睡眠恢复、饱和上下限、存档字段校验和分步推进。
- `python tools/test_pet_service.py`：编译生产存档/页面逻辑，模拟合并写入、重启、离线暂停、失败重试、不覆盖无效存档、输入节流和绘制边界。这是宿主测试。
- `python tools/smoke_pet.py --port COM9`：真实 UI 等待孵化、喂食、玩耍、清洁、睡觉、查看数值并退出保存，会真实改变宠物状态，不注入测试存档。
- 实机重启后 `python tools/smoke_pet.py --port COM9 --restore` 查看宠物和数值，人工比对恢复结果。截图在 `build/pet-smoke/`。

## 2026-10-21 COM9 实机记录

ESP-IDF 5.5.4 构建及发布校验通过，COM9 应用写入哈希通过。镜像 1,220,656 字节，较贪吃蛇版增加 4,208 字节，固定单槽余量 24,528 字节（约 24.0 KiB），未删除其他游戏。SHA-256 `d412e42932142123340c3dd48d7192d6d0b5e6a1c7fd160606fbeeb2d6d10107`。

真实 OLED 检查：初始蛋显示 HATCH IN 51s，按真实开机时间等待后变为 BABY 1m。实际执行喂食、玩耍、清洁、睡觉，数值页 FOOD 95 / MOOD 100 / REST 90 / WASH 100，显示 Z 和 WAKE。退出、重新进入仍是睡眠幼体。

随后通过 esptool 重启，仅读取页面而不追加照顾操作，恢复页仍为 BABY 1m、SLEEPING，四项数值与上述一致。原首页昵称和已有消息计数仍可见。日志未见崩溃或栈检查错误。当前宠物处于睡眠，旋转到 WAKE 后短按可唤醒。

这是孵化、照顾和真实 NVS 重启恢复的实测记录。30 分钟成体、长期后台数值变化和断电期间冻结的边界由宿主生产逻辑测试覆盖，尚未进行等时长实机或拔电故障测试；不能把此记录称为整机全部功能完整验收。
