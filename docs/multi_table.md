# 同一队伍里的多桌游戏

2026-10-30：同一频道、同一队伍 Room 可以由不同设备分别主持不同游戏桌，也可以开多桌相同游戏。每台设备同时主持、参加或观战一桌。桌游广播不再自动占据其他设备的当前对局。

新增游戏邀请、全员准备和只读观战，见[大厅与拓扑操作说明](game_lobby_and_topology.md)。

## 怎么用

1. 在设置 → 网络与连接打开自组网，使用相同频道；使用队伍时还要加入相同队伍代码。
2. 主持者进入趣玩 → 多人桌游 → 选择游戏 → 创建并担任主机。另一台设备可以照样创建另一桌，不必换 Room。
3. 其他玩家进入多人桌游末尾的“附近游戏桌”。也可先选某款游戏，再选“选择游戏桌加入”，只列出同款桌。
4. 列表显示游戏、桌主昵称、地址尾码/对局编号、人数和状态。选中一项先看详情；详情把游戏名、桌主、人数/状态、桌号分行显示。选择“加入或恢复我的座位”才发送加入请求；返回不会发送。
5. 每位玩家在大厅切换为准备；人数达到下限且全员准备后，由该桌主机开始。各桌按自己的规则和回合运行。
6. “我的当前游戏桌”回到本机已选对局；没有当前桌时会打开选桌列表。

例如 A 主持 UNO，B 主持情书；C 选择 A 的 UNO，D 选择 B 的情书，四台设备可在同一队伍中分别玩两桌。

## 列表与切桌

- 最多缓存八桌的公开信息；超过容量时替换较旧的非当前桌条目。八桌是发现缓存容量，不代表已经验证八桌同时满员的无线吞吐量。
- 约十五秒未收到有效公开状态，缓存中的桌会过期。主机也可能只是暂时丢包，因此不能据此认定主机一定关机。
- 列表在打开或点击“刷新游戏桌列表”时固定，避免滚动时条目换位。桌详情按相同身份更新人数和状态；已过期的选择不能加入，需要刷新。
- 已加入一桌且该局仍有效时，不能直接开新桌或加入另一桌；应先结束当前局。仍沿用现有“确认结束整局游戏”，参与者的这个操作也会结束全桌，并不是静默退座。
- 当前局结束、或所选主机已经失联时，可以选择另一桌。不支持同时参与两桌，也不支持中途插入新玩家；已开局的加入操作只允许恢复原有座位。
- 重启后不会自动选择听到的第一桌。要自行选回原桌恢复座位；主机重启会丢失内存中的对局。
- 切换频道或队伍会清空当前桌及发现缓存，私密手牌会重新遮挡。

## 通信与兼容

保留 COLLAB 20–24 的公开状态、私密状态、请求、回执和名单，新增 25 公开准备信息及 26 在线邀请，无新增 Flash 存档格式。发现表只缓存公开的游戏、昵称、人数、阶段和身份，不缓存其他桌手牌。公开状态供发现使用；只有玩家选定的桌可以更新自己的对局、手牌、名单或操作回执。

完整身份为“桌主 MAC + 桌主启动标识 + 对局编号”，不是只按游戏类型或桌号区分。同一桌主昵称、同一游戏甚至相同的启动标识/对局编号，也不会让不同桌主的数据串桌。这里是协议状态隔离，不提供加密或身份认证。

协议字节格式保持兼容，但旧固件会自动跟随先听到的一桌，缺少多桌选择。多人使用这项功能时，请统一更新固件。队伍外层分片和频道过滤继续沿用现有逻辑；不同 Room 之间不发现或加入彼此的游戏桌。

- `python tools/test_party.py`：两桌相同游戏并行、不同游戏发现和加入、同启动标识/同对局编号下的桌主隔离、异桌公开/私密/名单过滤、加入后锁定、失联过期、范围切换清空、八桌发现；保留十款规则 400 场完整模拟对局、八万次随机尝试及原有 ACK 丢失/重试/去重回归。
- `python tools/test_party_ui.py`：全部/同款列表、刷新、返回、详情确认、未确认不发送、离线选择不发送、完整桌主身份传参，以及换桌后私密信息重新遮挡。
- `python tools/test_personal_network.py`：128 字节公开状态在同队伍分片下，两位主机相同分片编号交错到达仍正确分别重组；保留原有房间隔离、资料卡、代存和存档回归。
- 中文字库、玩法说明、菜单和网络页面回归通过。构建结果见 `build/release/manifest.json`。
